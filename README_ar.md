# ميدان: خطوات التركيب (التحديث الثاني)

## 1) قاعدة البيانات (مرة واحدة)
في Supabase افتح SQL Editor، والصق محتوى `schema_v2.sql` كاملًا ثم Run.
(يُفترض أنك شغّلت `schema.sql` سابقًا.)

## 2) دالة إضافة الأعضاء (لإضافة الأعضاء من التطبيق)
1. في Supabase: Edge Functions ثم Deploy a new function ثم Via Editor.
2. الاسم: `members` (بالضبط).
3. الصق محتوى `supabase-functions-members/index.ts` ثم Deploy.
4. من إعدادات الدالة أوقف خيار Verify JWT (الدالة تتحقق من هوية المتصل بنفسها).

## 3) رابط الاستعادة (نسيت كلمة المرور)
- انشر `web-index.html` على Cloudflare Pages (باسم index.html). سيكون رابط الموقع.
- في Supabase: Authentication ثم URL Configuration: ضع رابط الموقع في Site URL وأضفه إلى Redirect URLs.
- افتح `config.json` وضع الرابط: `{ "webUrl": "https://اسم-موقعك.pages.dev/" }`.

## 4) بناء التطبيقين
ارفع محتوى هذا المجلد إلى مستودع GitHub خاص، ثم Actions ثم Build APKs ثم Run workflow.
ينزل ملفان: midan-manager (تطبيق المدير) و midan-member (تطبيق الموظف).

## 5) الاستخدام
- المدير يدخل بالبريد وكلمة المرور (حسابه الأول)، ويضيف الأعضاء من تبويب «الفريق».
- الموظف يدخل باسم المستخدم وكلمة المرور التي أعطاه إياها المدير.

# التحديث الثالث: اللاسلكي المباشر + تتبع الموقع أثناء الدوام

## أ) قاعدة البيانات (مرة واحدة)
في SQL Editor الصق `schema_v3.sql` كاملًا ثم Run (بعد `schema_v2.sql`). آمن لو شغّلته مرتين.
- يحفظ موقع الموظف **فقط أثناء الدوام** (من الدخول إلى الخروج)، ويمسحه عند تسجيل الخروج.
- يجهّز أسماء قنوات اللاسلكي السرّية (لكل محادثة اسم عشوائي لا يعرفه إلا من له حق دخولها).

## ب) اللاسلكي
- زر «اضغط مع الاستمرار للتحدث»: بث مباشر لمن يستمع على نفس القناة، **بلا تسجيل ولا حفظ**. متحدث واحد في المرة، ومن يحاول الكلام والقناة مشغولة يظهر له اسم المتحدث.
- زر «صوت» بجانب خانة الكتابة: رسالة صوتية عادية تُحفظ في المحادثة (إرسال أو إلغاء).
- الاستماع يعمل والتطبيق مفتوح (أي تبويب)، على القناة المختارة في المحادثة.
- إن ظهر «اللاسلكي غير متصل» ولم يكن السبب schema_v3: افتح إعدادات Realtime في Supabase وفعّل خيار Allow public access.
- حد الباقة المجانية 2 مليون رسالة Realtime شهريًا؛ استخدام فريق من 10 أشخاص بضع دقائق يوميًا يكفي بسهولة.

## ج) تتبع الموقع
- التطبيق يرسل الموقع كل 3 دقائق خلال الدوام (GPS ثم موقع الشبكة واي فاي/4G إن لم يتوفر GPS). لتغيير المدة عدّل `TRACK_MS` في `src/index.html` (120000 = دقيقتان، 300000 = 5 دقائق).
- لوحة المدير تعرض: المصدر (GPS أو الشبكة)، منذ متى، رابط الخريطة، وتنبيه «متأخر» إن انقطع الموقع.
- الموقع يشمل وقت الاستراحة طالما الدوام مفتوح.
- داخل APK الموظف: خدمة موقع بالخلفية (إشعار دائم «الدوام شغّال») تُضاف تلقائيًا في بناء `member`. عند أول دخول اسمح بالموقع «طوال الوقت». لم أستطع تجربة هذا الجزء على جهاز حقيقي، فجرّبه وأخبرني.

## التحديث الرابع (schema_v4)

**الخطوات:** (1) الصق `schema_v4.sql` كاملًا في Supabase ← SQL Editor ← Run (آمن لإعادة التشغيل). (2) تأكد أن الجداول الجديدة في Realtime (الملف يضيفها تلقائيًا). (3) ابنِ التطبيقين من جديد (GitHub Actions) أو انشر `web-index.html`.

**ما الجديد:**
- **المهمة:** قائمة «المواد المطلوبة» وقائمة «المواد المستخدمة» مع تحديد الموظف صاحب العهدة؛ يعدّلها رئيس المهمة والمدير. وقسم «مواقع المهمة»: مشاركة موقعك الحالي، أو لصق إحداثيات/رابط خرائط غوغل الطويل، مع فتح/اتجاهات/مشاركة، واعتماد موقع كموقع رئيسي للمهمة.
- **تبويب «المزيد»:** عهدة كل موظف (يديرها المدير، والموظف يرى عهدته فقط مع سجل حركات للمدير)، عدة الورشة وفي عهدة من، والسلف.
- **السلف:** كل موظف (ومشرف) يطلب سلفة بالدولار أو الليرة ويرى المسدَّد والمتبقي؛ صاحب الفريق وحده يوافق/يرفض ويسجّل السداد، ويرى سلف كل موظف على حدة.
- **منع التلاعب بالوقت:** وقت الدخول والخروج كان يُختم أصلًا من ساعة الخادم؛ الآن التطبيق نفسه يعرض ويحسب الأزمنة بساعة الخادم، ويُنبَّه المشرف في لوحة التحكم إن كانت ساعة جهاز موظف مغيَّرة (فرق أكثر من دقيقتين).

**افتراضات:** السلف بالدولار/الليرة؛ الموافقة = موافقة وتسليم؛ السداد دفعات تُسجَّل من صاحب الفريق؛ العهدة يديرها المدير؛ لا خريطة مدمجة (روابط خرائط غوغل).

## التحديث الخامس (schema_v5)

**الخطوات:** (1) الصق `schema_v5.sql` كاملًا في Supabase ← SQL Editor ← Run (آمن لإعادة التشغيل، بعد schema_v4). (2) ابنِ التطبيقين من جديد عبر GitHub Actions (أُضيفت إضافتا `filesystem` و`share` لحفظ ملفات Excel ومشاركتها). ملاحظة: التطبيق القديم لن يستطيع تصدير Excel حتى تثبّت النسخة الجديدة.

**ما الجديد:**
- **المهمة (للمدير والمشرف):** أزرار «تعديل المهمة» (العنوان والمكان والإحداثيات)، «إغلاق المهمة» / «إعادة فتح المهمة»، «حذف المهمة» (نهائي مع الصور والمحادثة). المهمة المغلقة تُقفل: لا يغيّر رئيسها حالتها ولا يضيف صورًا ولا يعدّل التقييم، ويظهر لها وسم «مغلقة» وتصفية خاصة بها.
- **البحث والطي في المهام:** خانة بحث (العنوان، المكان، رئيس المهمة، الأعضاء، المواد، الملاحظات) وأزرار «طيّ المهام حسب: اليوم / الأسبوع / الشهر / بدون طي». أحدث مجموعة تُفتح تلقائيًا، وعند البحث تُفتح كل المجموعات.
- **Excel:** تقرير الدوام (تبويب الحضور ← «تصدير التقرير (Excel)») ملف بورقتين: ملخص الساعات وسجل الدوام التفصيلي. تقرير السلف (المزيد ← السلف ← «تصدير تقرير السلف (Excel)») بثلاث أوراق: السلف، ملخص الموظفين، الدفعات. داخل APK تظهر قائمة المشاركة (واتساب، Drive، فتح بـ Excel…).
- **حالة الموقع:** زر «تحديث حالة الموقع» عند الموظف. إن أُغلق الموقع أثناء الدوام (أو رُفض إذنه) تُفتح له **استراحة تلقائية لا تُحتسب** حتى يفعّل الموقع ويضغط الزر (أو يصل موقعه تلقائيًا). يظهر ذلك للمدير في لوحة التحكم وسجل الدوام وعمود «موقع متوقف» في التقرير.
  - طريقة الكشف: فحص كل 45 ثانية والتطبيق ظاهر (فشلان متتاليان بسبب إغلاق الموقع)، وأي خطأ إذن من خدمة الخلفية، و**شبكة أمان على الخادم**: إن لم يصل أي موقع لموظف داخل الدوام 15 دقيقة تُسجَّل الفترة استراحة من آخر موقع معروف (يشمل من أغلق التطبيق أو الإنترنت). لتغيير 15 عدّل الدالة `loc_gap_minutes()` في `schema_v5.sql`.
- **لوحة التحكم:** كل مربع صار زرًا: الحاضرون، في استراحة (مع تمييز توقف الموقع)، لم يدخلوا، في إجازة، المهام قيد التنفيذ (مع زر فتح المهمة)، وبانتظار قرارك (طلبات المهام والإجازات والسلف مع أزرار موافقة/رفض مباشرة).

## التحديث السادس (schema_v6)
**خطوات التحديث (بالترتيب):**
1. شغّل `schema_v6.sql` في SQL Editor (بعد v5).
2. أعد نشر دالة `members` (الملف `supabase-functions-members/index.ts`).
3. ابنِ التطبيقين من جديد (APK).

**ما الجديد:**
- **دور «مدير»** أعلى من المشرف بصلاحيات صاحب الفريق (تصوير، إنهاء، إغلاق، حذف، إدارة الأعضاء…). صاحب الفريق وحده يضيف مديرًا آخر ولا يستطيع المدير تعديل مدير غيره.
- **انقطاع الموقع لم يعد استراحة تلقائية.** يسجَّل آخر وقت وموقع قبل الانقطاع وأول موقع بعد العودة، ويُراجَع السبب:
  - انقطاع شبكة/إنترنت (الجهاز سجّل نقاط موقع أثناء الانقطاع) ← **يُحتسب دوامًا**.
  - الموظف أغلق الموقع ← **استراحة** لا تُحتسب.
  - سبب غير معروف ← يبقى محتسبًا ويظهر للمدير في «بانتظار قرارك» وفي تبويب الدوام ليحسمه بزر.
- بطاقات الانقطاع في تبويب الدوام + ورقة «انقطاعات الموقع» في تقرير Excel.
- **مستودعان منفصلان لمدير الورشة:** مواد وعُدّة، يصرف منهما للمهام ويستردّ (من قسم المزيد).
